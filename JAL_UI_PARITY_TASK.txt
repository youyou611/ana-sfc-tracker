JALアプリのUI・操作統一 修正依頼
依頼元: 全体総括チャット
対象: JAL赤組用アプリ/
更新日: 2026-10-10
状態: 担当チャットへの転送待ち。総括監査でソースを確認。修正は未着手。

【目的】
ANA版とJAL版の基本的な操作・画面構造・状態表示をそろえ、航空会社別の色・用語・
計算・ブランド素材だけをそれぞれのアプリに残す。既存データと計算ロジックの根拠を
不用意に変更しない。

【優先度P0：設定とホームの目標値を一本化】
対象: app/settings/page.tsx、app/page.tsx、app/hooks/useFlightData.ts、必要なら app/lib/db.ts

現状確認:
- ホーム `app/page.tsx` は `useFlightData()` の `settings.jalTargetType` と `updateSettings()` を使う。
- 設定 `app/settings/page.tsx` は独自stateと `localStorage['jal_settings']` を直接使う。
- そのため両画面の目標ステータスが即時・永続的に同期しない。

受け入れ条件:
1. ホームと設定が、同じ永続化された目標設定を読み書きする。
2. 片方で目標を変更したら、もう片方にも反映する。少なくとも再表示・再読み込み後は一致し、
   可能なら共有フックによって同一セッション内でも即時に同期する。
3. 有効な既存 `jal_settings` の値を不用意に捨てない。既存キーからの互換読み込みが必要なら行う。
4. ANA側の設定状態管理パターンと整合するが、JAL用キー・FOP目標ラベルは維持する。

【優先度P1：JALカラーの残存漏れを修正】
対象: app/ClientLayout.tsx、app/page.tsx

現状確認:
- `ClientLayout.tsx` のスマホ下部タブのアクティブグラデーションと影がANA青色。
- `app/page.tsx` のNext FlightリンクとInformationカードが青色（青い点、青いグラデーション、
  青いボーダー・Betaバッジ・本文色）で、JALホームの赤系テーマと不一致。
- JALホームの `isJal = true` が定数なのにANA向けの青色分岐も残る。

受け入れ条件:
1. JALのアクティブなスマホタブ、ホーム内リンク、Informationカード、バッジはJAL赤系に統一。
2. 共通コンポーネントの形状、寸法、配置、アニメーション、操作方法はANA版と一致させる。
3. JAL専用アプリで不要な定数分岐が残るなら削除してよい。ただしコード整理だけを理由に大規模共通化しない。
4. PCサイドバー・モバイルトップバーの既存JAL赤色は維持する。

【優先度P1：詳細モーダルの保存結果を正しく表示】
対象: app/components/FlightDetailModal.tsx

現状確認: ANA版は失敗メッセージを赤、成功を緑で表示する。JAL版はメッセージを常に緑で表示する。

受け入れ条件:
1. 成功は成功色、保存失敗はエラー色で表示し、`role="status"` など既存の読み上げ対応を維持。
2. 機材情報、写真、メモの保存失敗が成功したように見えない。
3. 写真や既存搭乗記録の削除・置換処理を不用意に変更しない。

【優先度P1：往復登録の復路情報】
対象: app/calc/jal/page.tsx

現状確認: 往復登録時、復路レコードにも往路と同じ便名・機材・機体番号・座席・クラス・塗装を
複製する。同一路線の往復でも別の便・機材・座席となり得る。

受け入れ条件:
1. 復路の便名・機材・機体番号・座席を独立入力できるか、未入力なら復路には複製しない。
2. 運賃総額の往復按分、FOP/LSP計算の既存意味を保ちつつ、復路の記録日を正しく使う。
3. 往路・復路の入力値と登録結果が対応する。

【優先度P2：JAL設定のデータバックアップ】
対象: app/settings/page.tsx、既存 `app/lib/db.ts` のバックアップ関連機能

ANA設定画面には履歴・画像・設定のJSONエクスポート/復元がある一方、JAL設定には目標とガイド
しかない。JALも写真付き履歴を保存するため、データ保全機能のパリティが必要。

受け入れ条件:
1. JALの履歴・関連画像・設定をエクスポートし、同一アプリに復元可能にする。
2. 復元時に既存データを黙って消さない。同じIDは定義された方法で統合し、必要なら確認を表示。
3. ANA用フォーマットと誤って混同・上書きしない。JAL専用の識別子・検証・エラー表示を用いる。
4. 画像参照が壊れないことを確認する。安全な復元方法が既存実装だけでは難しい場合、まず設計を報告する。

【統一ルール】
- 共通化する: ページ階層、主ナビゲーション、履歴カードの情報配置、詳細モーダルの基本構造、
  タップ/キーボード操作、ローディング/空/保存エラー/成功の表現、レスポンシブ動作。
- JAL専用として維持: 赤系ブランド、FOP・LSP、JGC等の目標、クラスJ/ファーストの運賃、
  JAL/oneworld機材画像、国内線・国際線の別ルート構成。
- ANA専用を持ち込まない: PPラベル、ANA向け説明文、スターアライアンス画像選択や青いブランド装飾。
- 国際線TPM表が限定的なこと、LSPの累積丸め未対応は既存の制約として既に計画書に記録済み。
  UI整合の作業で隠したり、裏付けなしに計算ロジックを変更しない。
- 国内線運賃×搭乗クラスの公式条件は別の計算精度課題。JAL公式根拠を再確認してから別途報告し、
  本タスクで推測の計算変更をしない。

【検証と報告】
作業前に PROJECT_PLAN.txt と AI_WORKING_GUIDE.txt を読み、変更中のファイルを確認する。
変更後はJALアプリ内で必要な lint / TypeScript / build を実行し、可能ならPC・スマホ幅で
ホーム、ナビ、履歴詳細、設定、国内/国際計算機の操作確認を行う。
変更ファイル、実行したチェックと結果、既存データへの影響、未解決点を総括へ報告する。
ブラウザー操作や実機確認をしていなければ、その旨を明記する。
